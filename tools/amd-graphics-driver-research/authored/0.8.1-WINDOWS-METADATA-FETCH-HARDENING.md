# AMD Graphics Driver Research Toolkit 0.8.1 — Windows Metadata Fetch Review and Hardening

作成日: 2026-08-11

## 1. 結論

Windows PowerShell 5.1 の 0.8.0 再実行は、ローカルディレクトリ再構成のパス解決エラーではなく、21件のcurated product metadata取得の最後の2製品でAMD support pageが `HTTP 403 Forbidden` を返したため `MetadataCompleteness=Partial` となり、Acquireがfail-closedした。

Evidence上のProductMetadata処理時間は約 6.98 秒で、19/21までは取得成功後、Ryzen PRO 5000 / Ryzen PRO 8000の代表ページ2件だけが403となった。

0.8.1では、この種の一時的なproduct-page取得失敗を「catalog欠落」と即断せず、bounded retry/backoff、request pacing、同一ProductGroup内のAMD公式alternate representative page、Previous Driversの独立取得を追加した。それでもcoverageを回復できなければ従来どおりAcquireをBLOCKする。

## 3. 原因評価

直接原因はAMD support page requestに対するHTTP 403である。Evidenceにはローカルpath-not-found、public/private directory resolution failure、cache path exceptionは記録されていない。

public/private再構成により従来runのpage cacheを再利用しにくくなったことはlive requestへの依存度を上げる要因になり得るが、HTTP 403そのものをローカルディレクトリ再構成の直接原因とは判定しない。

21製品を短時間に連続取得した最後の2件で403となったため、AMD側edge/WAF/rate controlの一時応答である可能性はある。ただしEvidence単独ではrate limitingを証明できないため、`PlausibleNotProven`として扱う。

## 4. 0.8.1 hardening

### 4.1 bounded retry / pacing

新規parameters:

```powershell
-ProductMetadataRetryCount 3
-ProductMetadataRequestDelayMilliseconds 350
```

retry対象:

```text
403, 408, 425, 429, 500, 502, 503, 504
transport failure without status
```

404等のnon-transient failureはretry stormにしない。

### 4.2 same-product-group fallback

primary provenanceを維持したまま、同一ProductGroup内のAMD公式代表製品pageをalternateとして定義する。

- Ryzen PRO 5000: `5755GE` -> fallback `5750GE`
- Ryzen PRO 8000: `8700G` -> fallback `8700GE`, `8600G`

fallback成功はproduct-group代表取得のrecoveryであり、「primary model pageの取得成功」とは記録しない。

### 4.3 Previous Drivers independence

CuratedProductGroupsではlatest pageが取得できなくてもPrevious Driversを独立して試行する。0.8.0の `PreviousFetchStatus=NotRequested` により履歴情報まで失っていた問題を解消する。

### 4.4 provenance

`product-driver-mapping/1.2`へ、requested/effective URL、Primary/Alternate source、attempt count、retry/fallback recoveryを追加する。HTML cacheにはsidecar metadataを保存し、fallback HTMLを後続runでprimary URL取得済みと誤表示しない。

### 4.5 publication fail-closed

`ReviewRequired` / `FatalError` runでは `public/**` を更新しない。前回validated public baselineを保持する。GitHub Actionsがpartial metadata runを自動commitすることを防ぐ。

### 4.6 downstream summary

AcquireがBLOCKEDした場合、Extract / Inspect / Build関連assessmentは追加のmissing-file REVIEWではなく `SKIP` とする。原因を1件のupstream metadata failureへ収束させる。

## 6. Windows confirmation gate

0.8.1のlive AMD metadata recoveryはWindows PowerShell 5.1で再確認が必要。最初はdownloadを伴わない以下を推奨する。

```powershell
.\Invoke-AmdGraphicsDriverResearch.ps1 -Stages ProductDiscover,ProductMetadata,Select
```

期待条件:

```text
MetadataCompleteness = Complete
latest/previous unresolved failure = 0
RecoveredFetchProductCount / FallbackFetchProductCount は0以上（回復不要なら0）
21 product groupsを保持
```

Complete確認後にfull runへ進む。
