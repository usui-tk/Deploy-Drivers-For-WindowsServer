## 0.7.3で残っていたlog-quality issue

Test stageのunsupported-schema negative testは意図した試験であり、self-test自体はPASSしていた。

しかし0.7.3では内部で`throw`した例外をcatchする方式だったため、Windows PowerShell transcriptには:

```text
PS>終了エラー(): "Unsupported driver-packages assessment schema [...]"
```

と記録された。

これは実run failureではないが、第三者reviewでは実障害に見える。

0.7.4ではunsupported schemaを例外ではなくstructured `REVIEW` assessmentとして返し、self-testもその結果を検証するよう変更した。最終Testでは不要な終了エラー表示が消えた。

## 0.7.4 hardening

### ArtifactPipelineConsistency

full product-driven runで以下の4つを相互検証する。

```text
selection-plan.json
acquisition.json
extraction.json
driver-packages.json
```

検証内容:

- SelectedArtifactsから導出したArtifactKey集合
- Acquisition ArtifactKey集合
- ExtractionComplete ArtifactKey集合
- Inspected ArtifactKey集合
- Acquisition SHA-256とExtraction InstallerSha256
- estimated/actual download bytes

不一致があればFinal Assessmentを`REVIEW`にする。

### RunAssessment self-test

Test stageは以下を追加確認する。

- current index schema
- historical index schema
- unsupported schema -> structured REVIEW, no throw
- valid Select -> Acquire -> Extract -> Inspect chain

### Canonical baseline

今回のWindows-qualified Build出力をdevelopment packageへ反映した。

```text
Canonical artifacts 27
Cumulative drivers  551
Server rows         2,204
```

run-scoped acquisition/extraction absolute pathはcanonical packageへ取り込まない。

## 既知のprovenance note

3件のOS-track evidence conflictは引き続き保持する。これはAMDページ近傍labelとinstaller filenameのOS情報が一致しないケースで、既存のfilename override policyによってeffective trackを決定しつつ、conflictを消さずEvidenceへ残している。

ArtifactRole transition track 21件も同様に研究証拠として保持する。

これらは今回のrun failureではない。
